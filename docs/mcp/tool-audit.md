# MCP 工具筛选

## 准则

MCP 只接口化 WPE 已有的、用户能在现有界面或既有业务入口中读取或操作的能力。不得为 AI 单独创造业务功能、诊断结论或控制权限；候选工具不注册到 Sidecar，待 WPE 原生入口出现后再评估。

## 保留

保留所有直接映射到现有 WPE 页面、列表、编辑器、设置或业务动作的工具：抓包/日志、滤镜 CRUD 与启停、代理监听和设置、账号 CRUD/启停/原生登录记录、连接与账号列表、防火墙及规则、发送器/机器人紧急停止、启动模式选择，以及文本比对、编解码和数据提取页面能力。账号“登录记录”保持 WPE 原始语义，不伪装为不存在的设备库存。

滤镜工具还保留原生工具条和右键菜单的批量启停、计数重置、移动、复制、清空，以及“封包添加到滤镜”。滤镜导入/导出必须由 WPE 原生文件选择器和（可选）加密口令对话框完成，当前不具备 AI 独立完成条件；“试运行”没有对应的 WPE 原生页面或业务入口，均不注册。

抓包与分析保留代理和注入两份原生抓包列表、按需字节详情、原生正则“查找下一个”、日志、编码转换、重复字节比对与数据提取。列表导出、清空和跨模块“添加到发送/仓库”分别依赖原生文件框、会影响全局运行数据或属于后续发送器/仓库模块，因此在对应模块评估，不为抓包模块另造绕行入口。

## 候选池（暂不公开）

| 工具 | 原因 | 重新纳入条件 |
|---|---|---|
| `wpe_connection_get` | WPE 只有认证/客户端列表，没有原生“单连接详情”入口。 | WPE 增加可由用户打开的单连接详情页。 |
| `wpe_proxy_capabilities_get` | 构建能力快照不是当前用户可操作页面。 | WPE 增加对应能力展示页。 |
| `wpe_proxy_health_get` | 组合式健康结论不是现有原生功能。 | 先作为 WPE 原生诊断页面设计、验证。 |
| `wpe_storage_health_get` | 数据库健康元数据不是现有原生功能。 | WPE 增加原生存储诊断入口。 |
| `wpe_proxy_failures_list` | 对日志的 MCP 专用筛选摘要，不等同于现有日志页。 | WPE 增加同口径的原生日志视图。 |
| `wpe_executors_detail_get` | MCP 专用计数摘要；现有执行器列表已覆盖用户可见状态。 | WPE 增加同口径的原生汇总。 |

候选代码可保留在分支中供后续参考，但不应出现在 `tools/list`、Schema 或公开工具表。
